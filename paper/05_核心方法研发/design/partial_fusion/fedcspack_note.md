# FedCSPACK primary-text check

Source: *Tackling Resource-Constrained and Data-Heterogeneity in Federated Learning with Double-Weight Sparse Pack*, arXiv:2601.01840v1, https://arxiv.org/html/2601.01840v1 . Existing local HTML and text in `../literature_followup/fedcspack.html` and `.txt`, inspected 2026-11-03. No training or author-code validation.

- **Upstream selection, on client:** Method / “Top-k Based Cosine Parameter Packing”, Eqs. (3)-(5): client computes whole-model cosine θ_a and per-packet cosine θ_i,j, selecting packets with θ_i,j < θ_a by the surrounding method text. K is obtained by TopK( PW_i,j, θ_i,j, θ_a ); the formula itself does not define a full ordering/tie rule or fixed K budget. Introduction instead says “highest similarity”; record this wording inconsistency instead of silently choosing an interpretation.
- **Upload mask is weighted, not only binary:** Eq. (6) uses selected packet cosine, otherwise 0; Eqs. (7)-(8) add β_i,j = Σ PW_i,j log(PW_i,j/PW_j) at the client, so mask selected entries are θ+β. Raw weights can be signed, but text around (7) does not specify positivity/probability normalization, smoothing, or conversion before calling this KL. This is an implementation ambiguity, not grounds for guessing the actual implementation.
- **Server:** “Mask Double Weight Aggregation”, text immediately preceding Eq. (9): M^(t+1)=Σ_i M_i^t. Eq. (9) normalizes selected packet contributions by total weight at that packet: Σ_i (M_i,j/M_j) PW_i,k. Surrounding text adds this result to old global packet. Alg. 1 line 15 computes ΔW, but Eqs. (3)-(9) keep using local/global parameter packets; whether transmitted/added object is absolute parameters or deltas is not made consistent in these displayed equations. Requires author-code check before faithful implementation.
- **Downstream:** Alg. 1 line 8 sends W^(t+1), M^(t+1) to all clients. “Top-k...” first paragraph says PW_i[j] ← PW_global[j] if global M[j]=Valid; all other local packets retained. This is selective **application** of global parameters. It does not establish sparse downlink transmission, per-recipient beneficialness, or recipient-local validation.
- **Who decides “good”:** client-side cosine/KL proxies choose and weight uploads; server performs structural alignment and weighted aggregation. There is no additional server quality-test dataset / loss comparison in Alg.1 or Eqs.(3)-(9), and client downstream replacement is driven by common global-mask validity, not local loss/gradient improvement. “Most contributing” / “high-quality” are author interpretations of those proxies, not a separately defined tested criterion.
