# Development-only lambda sensitivity

The frozen primary method, data, states and official TEST results stay unchanged. This analysis uses saved development TRAIN logits/labels to fit a twenty-parameter centered affine predictor and development holdout logits to score it; it never reads official TEST or original images. The grid is fixed before execution: 0, 0.1, 1, 10, 100 and infinity. The objective and Newton/Armijo schedule are identical to the frozen solver, with the ridge coefficient changed only in this new process. Finite states are rounded once to FP32 before scoring. Infinity uses A=1,b=center(log(count+1)), rounded FP32. Lambda10 is checked against the existing FP32 state bitwise and its scores against the saved development metric.

All twenty clients in each task's fixed partition have at least one TRAIN-absent class. At lambda0 the multinomial cross-entropy has no finite minimizer: decreasing absent-class logits while compensating by a shared shift preserves centered bias and strictly decreases the loss. Thus lambda0 is recorded as a non-attained objective infimum, not a finite fitted state or fabricated NLL endpoint. The limit of the objective removes regularization, but a finite limiting estimator is not guaranteed.

Runs: exactly the existing three training seeds/task, with twenty clients/seed. Metrics: per-client holdout NLL and accuracy, client-macro seed mean, mean and sample SD across three seeds. No lambda or state is selected using any holdout/TEST result. This is a sensitivity diagnostic, not a new primary evaluation. Original evidence and source bytes are hashed before/after. Outputs only in this directory.
